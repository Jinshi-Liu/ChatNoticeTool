# 性能验证与日常快路径

## 最少的日常操作

```text
read → 当前Agent批量看图/理解 → write --input -
```

read返回本页精简消息及已授权纯图片路径；write一次提交待办和逐条处理结果。无需先写请求JSON、重复检查账号/取钥、扫描所有群或例行读取XML。看图仍由当前Agent完成，不能通过工具准备过图片就自动记为已理解。

## 可复现的合成基准

在项目目录，使用已有项目Python执行：

```text
python -B -X utf8 tests/benchmark_workflow.py --runs 10
python -B -X utf8 -m unittest discover -s tests -q
```

基准每轮在临时测试项目生成4张图片、1条同群图片引用、1条文字消息及1个待办；实际执行CLI分派、UTF-8 stdin、图片定位/转换、SQLite写入与完成去重。客户端消息查询是模拟的，不读取个人config、聊天、密钥或待办。测试完成会删除本轮合成资料，不清理实际用户数据。

程序分别报告兼容分步链路（read/prepare/todos apply/commit）和合并链路（read/write）的中位数、最小/最大毫秒数、CLI调用数、数据库对象初始化次数及SQLite连接次数。计时不含外部模型推理/看图、shell启动和真实聊天数据库解密，因此不能作为真实端到端速度承诺。不要把某次毫秒数波动当作稳定加速比例。

此合成负载的结构性工作量：

| 指标 | 同步的上游合并链路 | 本次继续优化后的合并链路 |
| --- | --- | --- |
| CLI调用 | 2 | 2 |
| 处理库对象初始化 | 4 | 2 |
| 待办库对象初始化 | 2 | 1 |
| SQLite连接 | 25 | 17 |
| 已有数据库重复写版本头/执行建表语句 | 有 | 无（仍检查身份、版本及必要表/索引） |

后续同群图片引用可跨批次命中原图缓存，不重复定位或转换；缓存每次复核授权和文件指纹，不能跨账号/群借用。测试同时覆盖撤权、资源变化、未知附件、分页不重解密、部分失败及中断幂等重放。`test_cli_process.py`还通过真正的独立Python进程与stdin走通可移植文件收件箱，覆盖文字/PNG图片、分页、删除原文件后续读、图片缓存、撤权、幂等重放及待办读取；图片夹具由标准库生成，无需Pillow，不只是模拟函数调用。单条消息候选待办关联超限也在写入前拒绝，不留下无法记账的半批任务。

## 避免宽历史授权空扫

授权起点不是首次日常读取的获取游标。没有游标且未传--since时，从授权范围内最近max_days窗口开始（默认7天），明确返回history_available_before/history_notice，较早历史仍未扫描；所有历史授权和数据均不修改，已接收的旧pending也不会被视为已处理。

用户明确要求历史时，传--since及可选--until，按返回的窗口续读。已有历史追赶游标仍向前推进，不因本优化跳到最近窗口。首次近期初始化后的获取游标也不代表已经扫描全部授权历史。

## 实际慢在哪里，用timings区分

对已授权的实际使用请求可加--timings；开发回归仍使用合成数据。内部指标包括：

- sources：读取来源数、快照数及选中行数。
- snapshot_phases：capture_seconds（复制和完整文件哈希校验）、derive_keys_seconds、main_decrypt_seconds、wal_replay_seconds、sqlite_check_seconds。
- decrypted_pages / wal_committed_frames：实际认证解密页及已提交WAL帧的工作量。
- query_seconds / decode_seconds / dedup_persist_seconds：查询、正文解码及持久化。
- attachment_prepare：定位/转换、缓存命中、直接路径命中及每群回退遍历次数。
- write：待办写入、处理记账和总耗时。

模型推理、图片输入传输及工具往返必须由调用端另测。当前没有常驻服务或跨请求全量解密快照缓存；首次读取仍可能完整复制/认证解密微信的多个消息分片。若此项占主导，应另行设计和验证可靠的增量/快照机制，不用陈旧文件替代新消息，不跳过页面认证、WAL或SQLite一致性校验来制造加速。
