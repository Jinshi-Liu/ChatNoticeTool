# 最短任务链与运行性能

## Agent 的日常路径

```text
read → 理解正文 / 看图 / 读文档 → write --input -
```

这里优先减少 Agent 的工具往返和准备步骤，而不是追求脚本跑得更快：

- 已有授权直接 read，不重复 inspect、列群或取钥。
- read 一次返回消息和本页图片；文档需要时加 `--attachments`。
- 待办操作和消息结果一次 write，不先创建请求文件，不分步提交。
- 同批分页用返回的游标续读，不重新读客户端。
- 没有消息就结束；没有待办变化只提交处理结果。
- 已明确的需求和授权直接执行，不为同一事项反复询问。

根目录 `AGENTS.md` 默认空白；用户自行填写处理习惯。工具文档说明接口，不充当必须逐轮执行的检查清单。

## 已保留的运行机制

多群按账号合批、共享快照；消息按身份和内容去重；图片缓存复用；写入通过操作 ID 重试，并保留用户编辑和完成状态。
默认只准备本页图片，按需读取文档和完整原文，不例行展开全部附件或 XML。

首次没有游标时读取最近 `max_days` 窗口；显式 `--since/--until` 用于更早历史。
