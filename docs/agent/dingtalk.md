# 钉钉V3实验读取

来自[@Jy66466的PR #1](https://github.com/Jinshi-Liu/ChatNoticeTool/pull/1)的群聊识别、消息字段映射和V3解密思路，整合进现有来源接口。没有新增日常工具、独立探测流程或待办判断模块。

**当前仅有合成测试，尚未验证真实钉钉客户端版本。**能力标记experimental；仅声明Windows本地V3群聊文本，不承诺V2、所有版本、云端/实时历史、图片、语音、文件或卡片。

## 一次配置，仍然read/write

先确认本人账号目录、真实UID和允许交付给当前Agent的群/时间。使用现有source configure（expected_revision取当前输出）：

```json
{
  "expected_revision":0,
  "confirmed":true,
  "platform":"dingtalk",
  "name":"本人钉钉（实验）",
  "uid":"12345678",
  "paths":{"account_dir":"D:/example/DingTalk/synthetic_v3"}
}
```

上面UID、目录均为虚构占位，必须由用户明确提供。UID不是显示昵称或组织ID；工具不跨账号日志猜UID，不扫描内存，不安装其他解密器。source candidates --platform dingtalk可有界列目录元数据，自定义位置用--base明确指定；不读取重定向配置或全盘搜索。

然后groups list取得群ID；groups plan/apply按[配置指南](configuration.md)确认每群规则与正文交付。单聊、不存在的会话、超出配置范围的请求均拒绝，组名不能替代准确群ID。日常仍是：

```text
read → 当前Agent理解 → write --input -
```

发送者保留UID，不额外查询全账号联系人。处理本地已有消息，不宣称云端/客户端尚未同步内容也已读取。只查询所选群和时间，但共享数据库的私有临时副本可能含其他会话页面，与已有读取器边界一致。

## 未支持内容不会消失

图片、文件等非文本消息只返回类型及必要标识，正文/下载元数据不交给Agent，标为不支持的待处理项；不能作为done提交。Agent应报告限制，或仅在用户明确允许后带原因skipped。不下载、不执行、不根据关键词自动生成任务。

同群跨消息分表会全部查询。相同稳定ID的相同内容去重；存在冲突副本则明确失败，不猜覆盖顺序。未知JSON、二进制正文和缺失字段不伪装为空通知。分页、去重、幂等、字段基线、撤权和失败恢复沿用现有处理库，不另建钉钉状态库。

## 快照与完整性边界

- 主库与WAL复用全文件哈希稳定快照；复制期间checkpoint导致不一致会重试，无法稳定则失败，不接受混合时点数据。
- 校验原始WAL头、帧链及提交边界后，直接回放完整提交前缀到临时主库；不靠重写校验值“修复”坏输入，也不让SQLite代为恢复来源WAL。
- 原始帧链允许完整匹配密文或明文校验表示之一，不能中途切换。完整帧校验失败则拒绝；不完整尾部及旧代尾部不越过最后完整提交继续读取。
- 主库必须完整对齐4096字节，首页及SQLite结构检查通过后才查询。临时明文只在本项目runtime/dingtalk-snapshots内，正常退出/异常处理后清除，不写原账号目录。
- **此V3 AES-ECB格式没有页MAC。**WAL校验与quick_check不是密码学认证，不能承诺识别所有有意篡改的主库数据；这不等于QQ/微信已有的页认证能力。凭据派生仅在内存中进行，不输出密钥片段或所谓“密钥指纹”。

source check只验证配置及解密首页结构，返回format_candidate，不等于已完成真实客户端兼容性验证。日常不重复check。测试只用合成账号/SQLite/加密页，开发不读取真实聊天、日志或个人配置。欢迎补充明确的格式资料和合成测试，不提交真实UID、密钥或聊天数据库。
